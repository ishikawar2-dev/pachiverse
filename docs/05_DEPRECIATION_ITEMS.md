## 1. 目的と使い方（評価人向け）

- 本メモは、再調達原価（工数表 第 4 章、外注見積 2〜3 社で裏付け予定）から**控除すべき陳腐化・減価の要因**を、売り手が自ら列挙したもの。
- 各項目に「事実」「金額レンジの根拠」「2026-09-15 時点の状態」「根拠資料の所在」「評価への影響の性質」を付す。**係数（再調達原価の何割か）は書かない**。控除額の決定は評価人が独立に行う。
- 金額は工数表 第 7 章・付録 B の値をそのまま用い、本メモで新しい金額は作らない。工数表にない項目は「金額未算定」とし、算定に必要な根拠だけ示す。
- 「影響の性質」は 2 種類に分ける。**(a) 取得後費用** = 買い手が取得後に負担する費用（改修・監査・移行）。**(b) 原価減額** = 再調達原価そのものが過大である可能性（単価・工数の見直し）。
- 解消済み・解消予定の項目は §4 に集約した。評価時点（監査後、12 月〜2027 年 1 月を想定）で状態を再確認し、解消済みは控除から外す。

## 3. 項目ごとの詳細

### 3.1 改修費（技術的負債、工数表 第 7 章の 8 項目）

**A-1 鍵管理（60〜100 万円）**。工数表 v1.1 時点は「コード実装済み・実施は 9/10 以降」だったが、9/15 時点では次まで進んだ: 移行方式は既存 3 鍵を Google Cloud KMS（HSM）へインポート（新鍵切替なし）、2026-09-14 に捨て鍵でインポート→署名→アドレス復元一致のリハーサル成功、未決事項 8 件（Q-4/Q-9/Q-10/R-1〜R-7）はオーナーが 9/15 に確定し runbook §6 に反映。前提作業 finalizeMinting（9/8）・freezeMetadata（9/14）は完了。**未実施**: signer PR #1/#2 と members PR #51 のマージ、本番鍵インポート（Part A、後戻り不可）、移行翌日の実 TX 検証、VM 平文の後始末。KMS 利用料は月 $7.5 前後（Q-9）。控除は「実施の残工数」に限定してよいが、実施完了までは工数表の値をそのまま置く。

**A-2 ADMIN 集中（40〜60 万円）**。Safe 2-of-3 の署名者は確定（会社 MetaMask・オーナーの Ledger・新規調達の 2 台目 Ledger）。Safe へ移すのは DEFAULT_ADMIN_ROLE のみ。2 台目 Ledger の調達（オーナー）と Part A 完了が前提のため、実施は Part A の後（10 月中の見込み）。旧 ADMIN の除去は Safe 経由の `revokeRole`（R-6）。

**A-3 単一障害点・属人性（80〜130 万円）**。Signer は nonce 管理のため 1 インスタンス固定（`docs/KNOWN_ISSUES.md`「絶対に壊してはいけないもの」）。運用は PO・実装・レビュー・デプロイ承認・鍵操作が 1 名に集中し、2 人目の担当は未選定（03_TRANSFER_PLAN §5）。9/15 に稼働・インシデント記録（`ops/OPERATIONS_LOG.md`）を新設し週次更新を開始したが、2 人目のハンズオン・復旧リハ・デプロイ自動化は未着手。付録 B-7「運用の複数名化と手順の外部化」80〜130 万円は本項と同一内容のため重複計上しない。

**A-4 法務（100〜170 万円）**。カストディアル方式の資金決済法該当性・払出時課税・KYC・景表法/賭博該当性は要件定義書 §8 が弁護士確認を推奨したまま未実施。今回の譲渡ではスコープ外と決定したため、控除項目として残る。買い手の DD で必ず問われ、結論次第で価値評価の前提自体が変わる（減価ではなく go/no-go 要因）ことを評価人に明示する。

**A-5 第三者監査（100〜170 万円）**。10 月に監査スコープ（contracts / signer / WordPress）を確定し 3 社見積・発注、11 月開始、レポートは 12 月〜2027 年 1 月の見込み。指摘の是正費は未見積（03_TRANSFER_PLAN §5）。監査前に D（§0 未修正分）と F の既知問題を潰す計画で、既知の欠陥を有料で指摘されることを避ける。

**A-6 インフラ制約（70〜100 万円）**。共用レンタルサーバー（お名前.com）により固定 IP なし・常駐プロセス不可・WP-Cron の時刻保証なし。デプロイは FTPS の手動作業で、プラグイン本体と `inc/*.php` の配置順を誤ると fatal error（過去に発生、`docs/DECISIONS.md` 2026-09-01「本番デプロイ物は必ず main ベース」）。移行は移行リスクを伴うため、買い手が譲渡後に実施する選択肢もある（工数表 付録 B-9）。

**A-7 アート資産の版管理（10〜20 万円）→ 解消済み**。2026-09-15 に `pachiverse01-ai/pvm-art`（private）として Git 化し、trait マスター・合成実装・アンカー・最終 metadata・IPFS 復旧材料を追跡（約 90MB）。残るのは原本画像 10GB（`out/images4096/`）の別置きバックアップのみで、SHA-256 マニフェストによる照合は可能な状態。評価時点で控除から外してよい。

**A-8 事業実績の未文書化（40〜50 万円）→ 性質変更**。工数表は「会員数・売上・保有者数を資料化すれば収益還元法・市場比較法が使える」として資料整備費を計上したが、2026-09-15 に評価手法を原価法に固定し、売上に依存する手法は使わないと決定した（[DECISIONS.md](DECISIONS.md)）。したがって資料整備費としての控除は不要になる一方、「収益性の裏付けがない」事実そのものは E として残る。利用規模 3 段（登録 4,634／利用開始 1,721／90 日活動 711）は稼働の証拠としてのみ添付し、顧客基盤の資産計上には使わない。
