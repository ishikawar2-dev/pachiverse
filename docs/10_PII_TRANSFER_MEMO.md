## 1. 目的

知的財産権の譲渡（オーナー個人 → 株式会社 UNI。契約形式は知財譲渡契約、DECISIONS 2026-09-24 U-5）に伴い、会員サイト `members.pachiverse.com` の DB に含まれる会員の個人データを「誰から誰へ・どの根拠で」移すのかを整理し、次の 3 つを用意する。

1. 保有する個人データの一覧（§3）— 何を持っていて、どこにあり、誰に渡っているか
2. 法的整理の候補と弁護士に確認する論点（§4・§5）— 同意が要るのか、通知で足りるのか、そもそも「移転」が発生するのか
3. 会員向け通知文案 2 案（§6）と移管作業チェックリスト（§7）

前提（03_TRANSFER_PLAN §1、オーナー確定 2026-09-15）:
- オーナーは UNI の **100% 株主だが役員ではない**。代表取締役は別人
- IP（コード・アート・文書）はすべてオーナー帰属。会員サイトは **UNI の会員向け**に運用されている
- 会員データは UNI/VB の顧客データであり、**評価対象外かつ譲渡対象外**（譲渡するのはシステムと IP のみ。DECISIONS 2026-09-24 U-10）。DB は UNI の顧客データとして UNI が保持し続け、会員通知は不要（U-10）。本書の §2〜§6 は U-10 以前の整理で、§2.2 (A)「UNI が個人情報取扱事業者・オーナーは委託先」が U-10 と整合する第一候補。弁護士確認（§5）はこの前提で行う

### 2.2 個人情報取扱事業者は誰か（要確認 #1）

コードと文書から拾える事実は次のとおりで、**一方に確定できない**。

| 「UNI が事業者」を支える事実 | 「オーナー個人が事業者（少なくとも共同）」を支える事実 |
|---|---|
| 会員は全員 UNI/VB の既存顧客（公開登録なし、CSV 事前登録のみ。00_OVERVIEW） | サーバー契約・GitHub・GCP・Vercel・Cloudflare 等がオーナー個人名義（07 §2・§8） |
| ドメイン `pachiverse.com` / `vegasbank-nft.com` は UNI 名義（07 §8 #2） | 会員へのメールはオーナーの運用で送信され、署名は「Pachiverse運営事務局」（法人名の明記なし） |
| 初回案内メールが「株式会社UNI関連の…会員様へ」と名乗る（inc/auth.php） | 取込元データ（正規データ）はオーナーの Mac に置かれている（07 §2「正規データ」行） |
| サポート担当が UNI 側スタッフ（07 §5） | IP と運用実態はオーナー個人。UNI から既払い対価なし（03 §1） |

整理の候補（§4 で展開）:
- (A) **UNI が個人情報取扱事業者**で、オーナーは開発・運用の**委託先**（法 27 条 5 項 1 号相当）。この場合、譲渡は「委託の終了とデータの返還」に近く、第三者提供・事業承継のいずれも発生しない可能性
- (B) **オーナー個人が個人情報取扱事業者**（サイト運営の実態を重視）。この場合、譲渡は**事業承継に伴う提供**（法 27 条 5 項 2 号相当）として整理できる可能性
- (C) 両者が**共同利用**（法 27 条 5 項 3 号相当）していたが、公表要件（共同利用する旨・項目・範囲・目的・管理責任者）を満たしていたかは不明

### 2.3 会員規約・プライバシーポリシーの名義（要確認 #2）

- フッターは `/support/` ページでのみ「利用規約」「プライバシーポリシー」へのリンクを出す（`inc/header-footer.php`）。著作権表示は「© PV. All rights reserved.」で法人名なし
- 利用規約 `/terms/`・プライバシーポリシー `/privacy/`・特商法表記（固定ページ `law`）は **WordPress の固定ページ（DB 内）で、リポジトリには本文がない**。管理画面の一覧（`inc/admin-notice.php`）で存在は確認できる
- 過去の調査メモ（2026-09-12）によれば、プライバシーポリシーは公開・利用目的 3 つのみ、**特商法表記は非公開のプレースホルダー**。事業者名・住所・代表者名（法 32 条 1 項 1 号相当の公表事項）が誰の名義になっているかは**本番ページの実物で確認が必要**
- サポート FAQ（`inc/support.php`）には「旧サービスから個人情報が引き継がれているのはなぜですか」という項目が既にあり、「当社」が旧サービスの会員情報をもとに開設した、と回答している。この「当社」が UNI を指すのかは明示されていない

## 3. 保有する個人データの一覧（実装から棚卸し）

凡例 — 保存場所: WP = お名前.com 上の WordPress MySQL。保存期間: 実装上の自動削除がなければ「無期限（削除処理なし）」。削除の可否: 技術的に消せるか（法的に消してよいかは別）。

## 4. 譲渡時の法的整理の候補

**構図**: 譲渡人 = オーナー個人（UNI の 100% 株主・役員ではない）、譲受人 = 株式会社 UNI。移すもの = システム一式と、その中にある会員 DB（UNI/VB 顧客の個人データ）。

| 候補 | 内容 | 本件への当てはめ（可能性） | 必要になる手当て |
|---|---|---|---|
| (0) **移転が発生しない** | 個人情報取扱事業者が最初から UNI で、オーナーは委託先（§2.2 (A)） | 会員が UNI/VB の顧客であること、ドメインが UNI 名義であること、初回案内が UNI を名乗ることと整合する。この場合、譲渡は「委託の終了に伴う返還」で、**本人同意も承継の整理も不要**と整理できる可能性 | 委託関係の証跡（契約書がない場合は覚書で遡及整理できるか）、委託先としての安全管理措置の記録、Anthropic 等への**再委託**の扱い |
| (a) **事業承継に伴う提供**（法 27 条 5 項 2 号相当） | オーナーが事業者で、事業譲渡により UNI が承継（§2.2 (B)） | 「オーナー個人が会員向けサービス事業を営んでいた」と言えるかが前提。100% 株主からの自社への譲渡でも、法人格は別なので承継の形式は取り得ると整理できる可能性 | **本人同意は不要**だが、承継後は**承継前の利用目的の範囲内**でしか取り扱えない（法 18 条 2 項相当）。UNI が利用目的を広げる（購入導線・紹介制度など）なら別途同意または利用目的変更の手続き。通知は法定義務ではないが実務上推奨（§6 案 1） |
| (b) **委託**（法 27 条 5 項 1 号相当） | UNI がオーナーに運用を委託していた、または譲渡後にオーナーが保守委託を受ける（03 §4.1 策 5） | (0) と組み合わせて使う。譲渡後の保守委託契約で、オーナーが引き続きデータに触れる根拠になる | 委託契約書、委託先の監督（法 25 条相当）の記録 |
| (c) **第三者提供（本人同意）**（法 27 条 1 項） | (0)(a)(b) のいずれにも当たらない場合 | 最も重い手続き。4,634 人の同意取得は現実的でない（利用開始 1,721 人・90 日活動 711 人。06_USAGE_SCALE） | 同意取得の導線（§6 案 2）、同意しない会員のデータの扱い |
| (d) **共同利用**（法 27 条 5 項 3 号相当） | オーナーと UNI が共同利用していたと構成 | 公表要件を事後的に満たすのは難しく、主案にはしにくい | プライバシーポリシーの改訂 |

**推奨する整理の順序（弁護士確認前の仮置き）**: (0) を第一候補として事実関係を固め、(0) が取れない場合に (a) で整理し、いずれの場合も §6 案 1 の通知を出す。(c) は最後の手段。

**VB 由来データの注意**: VB が UNI と別法人であれば、上記の整理は「オーナー ⇄ UNI」だけでは閉じない。VB → 会員サイトへの取込時点の根拠と、譲渡後に UNI が VB 顧客データを保持する根拠を別途確認する（§5 論点 2）。
